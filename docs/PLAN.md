# 机巧 · 方案与验收标准

可拆解、可慢放的三维图解：从石磨到钟表的机械传动，以及榫卯结构。
本文件是实现代理的共同依据；与代码冲突时以本文件的「硬性约束」和「验收标准」为准，其余可在说明理由后调整。

- 定稿日期：2026-11-10
- 分工：Fable 5.2 出方案与验收；Opus 5.5 做复杂实现；Sonnet 5.5 做简单实现与调研

## 1. 目标

让一个不懂机械的人，通过转动、拆解、慢放一台三维机器，看懂两件事：

1. **每个零件是什么、做什么。**
2. **零件之间如何协同。** 运行时，力和运动沿哪条链传递，此刻是哪一环在起作用。

第二点是本项目的重心，对应每个展品的「协同链」。

不做：照片级渲染、物理引擎仿真、用户账号、后端、部署（部署需用户另行批准）。

## 2. 调研结论（2026-11-10）

| 问题 | 结论 | 依据 |
|---|---|---|
| 有没有可直接用的 JS 齿轮/擒纵/连杆库 | 没找到，需自己写 | npm 上 `involute-gear` 等包不存在；GitHub 搜索无对口 JS 库（搜索受限流影响，覆盖不完整） |
| 有没有许可证干净的中式榫卯三维模型集 | 没找到 | 对口的网页项目要么无许可证，要么 AGPL |
| 同类做法是否可行 | 可行 | `RealTube/calibre-m01-tourbillon`（MIT，three.js 程序化生成约 180 个网格的腕表）、`csciuto/calibre-bench`（MIT）都是「一个时间值驱动全部零件，擒纵用几何求解」 |
| 有没有通用的爆炸图 / 剖切组件 | 没找到成熟库，自己实现 | 相关搜索只有 0–1 star 的单品项目 |
| 中国古代机械有没有现成实现 | 只有指南车一例 | `hoveychen/zhinanche`（代码 Apache-2.0，模型 CC-BY-SA-4.0）。第二期做指南车时参考其模型约定文档；石磨、水碓、木牛流马、水运仪象台未搜到 |
| 参考站 Anatomy 的技术 | 等轴测 SVG，非真三维 | `wheresryan22/anatomy-figures`（MIT）。借鉴其方法，不用其代码 |

借鉴的方法（不复制代码）：

- 真值模型先行：读数、运动、文字说明都读同一个纯函数模型。
- 几何只建一次，运动只改位姿。
- 画面里只有一个强调色，给当前该看的零件。
- 每条陈述标注出处类别（来自 calibre-bench）。
- 齿轮啮合要对相位，不只是对速比（来自 calibre-m01-tourbillon）。

## 3. 技术栈

按适用性选择，版本为 2026-11-10 npm 最新。

| 用途 | 选型 | 理由 |
|---|---|---|
| 渲染 | three 0.187 + @react-three/fiber 9 + drei 10（WebGL） | 真三维的事实标准；声明式场景适合「零件即组件」。不用 WebGPU：兼容面更窄，本项目用不到其能力 |
| 几何内核 | manifold-3d 3.5（WASM，Apache-2.0） | 保证产出封闭实体；能算体积和交集，因此能**自动审计零件是否互相穿模**；能做带截面的真实剖切 |
| 运动 | 自写运动学纯函数 | 可慢放、倒放、拖动；物理引擎做不到，且对齿轮和擒纵的接触不稳定 |
| 应用 | Vite 8 + React 19 + TypeScript | 纯静态站点，无后端 |
| 状态 | zustand 5 | 展台状态小而集中 |
| 路由 | wouter 3 | 只有首页和展品页 |
| 样式 | 原生 CSS + 设计令牌（CSS 变量） | 界面小，不需要 CSS 框架 |
| 测试 | Vitest 5（模型与几何审计）+ Playwright 1.65（浏览器） | manifold 在 Node 里同样可跑，几何审计可进单元测试 |

没有采用的：Babylon.js（包体 73MB，功能过剩）、replicad/OpenCascade（B-Rep 内核过重）、three-bvh-csg（版本 0.0.x，且不保证封闭实体、无体积计算）、Rapier 物理引擎（见上）、外部 GLB 模型（无干净素材，且无法参数化）。

## 4. 架构：三层复用

```
src/
  kernel/       几何内核封装：初始化 manifold、Solid 辅助、转 BufferGeometry、体积与干涉计算
  kinematics/   纯数学，不依赖 three：齿轮系、连杆、凸轮、擒纵、装配序列
  kit/          参数化零件 → Solid：齿轮、轴、曲柄、连杆、凸轮、木料与榫卯特征、石件
  exhibit/      展品契约（类型）与注册表（import.meta.glob 自动发现，新增展品不改公共文件）
  stage/        统一三维展台：相机、灯光、零件网格、爆炸、剖切、时钟、协同链高亮
  ui/           页面外壳：展厅首页、展品页布局、零件面板、时间轴、读数、协同链面板
  exhibits/<id>/  每个展品一个目录：model.ts（真值模型）、parts.ts（零件）、content.ts（文字）、index.ts、*.test.ts
```

### 4.1 展品契约（核心，Wave 1 可细化，改动须写入 docs/AUTHORING.md）

一个展品 = 数据 + 纯函数，不含渲染代码：

```ts
type Provenance = 'source' | 'reconstruction' | 'hypothesis' | 'model' | 'calc'
// 史料原文 / 通行复原 / 假说 / 本站设定 / 计算所得（必须有测试）

interface Claim { text: string; provenance: Provenance; cite?: string }

interface PartDef<S> {
  id: string; name: string            // 中文名
  group: 'base' | 'structure' | 'mechanism' | 'control' | 'subject'
  material: MaterialKey               // 'wood-light' | 'wood-dark' | 'stone' | 'iron' | 'brass' | 'rope' …
  solid: (k: Kernel) => Solid         // 局部坐标系下的实体，只建一次
  rest: Pose                          // 装配完成、初始状态的位姿
  pose?: (s: S) => Pose               // 运动零件：位姿是状态的纯函数
  explode: { dir: Vec3; distance: number; order: number }  // 爆炸方向即装配路径
  role: string                        // 一句话：它做什么
  claims?: Claim[]
}

interface ChainStep<S> {              // 协同链的一环
  id: string; title: string; parts: string[]; text: string
  active?: (s: S) => boolean          // 运行中此刻是否正在起作用（用于实时点亮）
}

interface ExhibitDef<S, C> {
  meta: { id; title; subtitle; category: 'mechanism' | 'clock' | 'joinery'; era; summary; hypothesis?: boolean }
  controls: ControlDef<C>[]
  timeline: { kind: 'cyclic' | 'assembly'; period?: number; speeds: number[] }
  simulate: (t: number, c: C) => S    // 真值模型，纯函数：同样的 t 永远得到同样的状态
  parts: PartDef<S>[]
  chain: ChainStep<S>[]
  readouts: { label: string; value: (s: S) => string; provenance: Provenance }[]
  sources: Record<string, { title: string; text?: string; url?: string }>
}
```

榫卯展品用同一契约：`timeline.kind = 'assembly'`，`t` 是装配进度，协同链的每一环是「这一步插入后锁住了哪个方向」。

### 4.2 展台必须提供的能力

- 轨道旋转、缩放（朝指针处）、平移；自动取景（避开界面浮层）；选中零件一键凑近；展品可预设机位（相机 + 让开 + 剖切 + 爆炸一键到位）。触屏单指旋转、双指缩放平移。
- 播放、暂停、调速（含慢放）、拖动进度；榫卯为装配进度条。长周期展品另有只覆盖一个小循环的细调条与关键瞬间跳转（见 AUTHORING 第 5 节）。
- 爆炸滑块：按 `order` 错开，沿 `dir` 分离。
- 悬停高亮、点选零件 → 面板显示名称、作用、陈述及出处标签。
- 孤立显示：选中零件实体，其余半透明。
- 协同链面板：逐环列出；运行时实时点亮当前起作用的一环，点击某环则高亮其零件。
- 剖切：榫卯展品必须有**带截面的**剖切视图（看榫头如何坐在卯眼里）。
- 读数：全部来自 `simulate` 的状态。
- 键盘可操作；`prefers-reduced-motion` 下默认暂停；移动端宽度可用。

### 4.3 视觉方向

工笔图解，不追求照片级：浅色纸底，材质用克制的自然色（木、石、铁、铜），细墨线勾边，柔和阴影。全场只有一个强调色（朱砂），留给被选中或正在起作用的零件。提供深色主题。字体与间距走设计令牌。

## 6. 硬性约束

1. **不编造。** 每条陈述带出处类别；史料引文必须出自 `docs/sources/` 里核实过的原文，否则标为 `model` 或 `hypothesis`。没有把握的数字写成本站设定，不写成史实。
2. **运动只来自 `simulate`。** 任何零件不得自己随时间动画。
3. **几何来自代码。** 不引入外部模型文件。
4. **不复制第三方代码。** 可以实现公开的数学公式；借鉴了思路的仓库记入 `docs/CREDITS.md`。
5. **不加自动化与部署。** 不建 CI，不部署，不引入任何付费或需要密钥的服务。
6. **不弱化测试。** 审计不过就修几何或模型，不得放宽阈值来通过；确需调整阈值要在交付说明里写明原因。

## 7. 验收标准

自动检查（全部必须通过）：

1. `npm run typecheck`、`npm test`、`npm run build` 通过。
2. **实体审计**（每个展品）：每个零件是封闭实体且体积 > 0。
3. **干涉审计**：
   - 榫卯：装配完成状态下，任意两构件的交集体积 < 较小者体积的 0.1%；沿装配路径采样（每步不少于 20 个点）同样不穿模。
   - 机械：每个周期采样不少于 60 个相位，啮合或接触的零件对交集体积 < 较小者的 0.5%。
4. **运动学审计**：
   - 连杆：各杆长度在全周期内保持不变（误差 < 1e-6）。
   - 齿轮：角度满足齿数比，啮合相位正确。
   - 记里鼓车：足轮 100 转，中平轮恰好 1 转。
   - 摆钟：每个摆动周期擒纵轮恰好前进 1 齿；秒、分、时针速比为 1 : 1/60 : 1/720。
   - 鲁班锁：按给定顺序可无干涉地逐根拆出。
5. **浏览器检查**（Playwright，桌面 1440 与手机 390 两种宽度）：每个展品页加载无控制台错误；画布非空白；播放/暂停、调速、爆炸、点选零件、协同链高亮、剖切（榫卯）可用。

人工验收（Fable 5.2 看截图与实际页面）：

6. 每个展品一眼能认出是什么；爆炸状态下零件不重叠、不飞出画面。
7. 协同链的文字与画面一致：文字说哪一环在动，画面里就是那一环在亮。
8. 所有史料陈述能在 `docs/sources/` 找到原文。
9. 首页、展品页在两种宽度和深浅两个主题下没有溢出与遮挡。

不在验收范围、交付时须如实说明：真实设备上的帧率、触屏手感、读屏器体验。
